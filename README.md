# OLMAX

Каталог автомобілів і причепів: польська й українська мови, пошук, фото, звернення та кабінет власника.

## Оновлення на Railway

Репозиторій публікації: `Moran12214/OLMAX`. Нова версія готується в гілці `codex/olmax-release`.
Робочий сайт станом на 1 жовтня 2026 року використовує старий застосунок і PostgreSQL.
Ця версія використовує SQLite та файлове сховище фото. За рішенням власника новий сайт
починає з порожньої бази: резервна копія та перенесення старих записів не потрібні.
Файл `cars.db` у репозиторії використовується лише локально та в тестах і не входить
до Docker-образу. На новому порожньому томі таблиці створюються без оголошень і звернень.

Перед перемиканням робочого сервісу:

1. Додати **окремий порожній** Railway Volume до сервісу OLMAX, шлях монтування `/data`.
   Том PostgreSQL лишається при сервісі PostgreSQL.
2. Налаштувати змінні OLMAX: `DATA_DIR=/data`, `RAILWAY_RUN_UID=0`,
   `PUBLIC_ORIGIN=https://www.olmax.net.pl`, `COOKIE_SECURE=true`, `PORT=8080`,
   `ADMIN_USERNAME=admin` та `ADMIN_PASSWORD_HASH` із `tools/setup_admin.py`.
   Хеш і `.env` не додавати в GitHub. Після налаштування перевірити вхід у кабінет.
3. Перемкнути гілку Railway та перевірити порожній каталог і вхід власника.
   `railway.json` задає Docker-збірку, запуск із `PORT` та перевірку `/healthz`.
   Цільовий порт доменів — `8080`.

Ці кроки ще не виконані на Railway. Видалення старого PostgreSQL не входить до цього оновлення.
Попередня версія коду містила вбудований пароль PostgreSQL:
його слід змінити в Railway, синхронізувавши `DATABASE_URL` поточного сервісу.

Документація Railway: [Volumes](https://docs.railway.com/volumes),
[Config as Code](https://docs.railway.com/config-as-code/reference).

## Локальний запуск

Потрібен Python 3.13. Команди виконуються в папці проєкту.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python tools/setup_admin.py
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8766
```

Відкрити http://127.0.0.1:8766. Кабінет: `/admin.html`, логін `admin`, пароль задається локально командою вище. Пароль не виводиться на екран і не зберігається відкритим текстом. Після зміни пароля перезапустити сервер.

## Як користуватися

1. Увійти в «Кабінет власника» внизу сторінки.
2. Натиснути «Додати авто», заповнити поля та додати фото.
3. «Чернетка» зберігає авто тільки для власника. «У продажу» показує його в каталозі. «Продано» прибирає з каталогу, зберігаючи інформацію.
4. Перше фото — головне; порядок можна змінити кнопкою «Зробити головним».
5. Звернення знаходяться у вкладці «Звернення». Позначити «Зв’язались» або «Закриті» після обробки. Кнопка видалення назавжди видаляє дані цього звернення.

**Сповіщення email/SMS не підключені:** нові звернення треба перевіряти в кабінеті. Поля оголошення не перекладаються автоматично; кнопки та навігація перекладаються.

## Дані

У Docker на порожньому томі створюється порожня база. Наявна база на томі зберігається при повторних запусках. При першому локальному запуску стара `cars.db` копіюється в `runtime/cars.db`; початковий файл не змінюється. Тестове оголошення з назвою `test` стає чернеткою. Відомі тестові описи трьох інших оголошень очищаються одноразовою міграцією; замість них сторінка пропонує уточнити деталі телефоном. Фото, ціни й характеристики збережені як у прототипі — власнику варто перевірити їх перед публікацією.

Нові фото зберігаються в `runtime/media`, обмежені до 8 на авто, 5 МБ і 24 мегапікселів на фото. Сервер змінює розмір до 1920×1440 та видаляє EXIF. Старі фото лишаються доступними; при збереженні оголошення вбудовані фото також переносяться до файлів. Фото за зовнішнім HTTPS-посиланням залежать від доступності стороннього сайту.

`runtime/` та `.env` не можна видаляти при оновленні. Не класти всю папку проєкту в публічний `public_html`: база та конфігурація мають лишатися приватними. Сервер віддає лише дозволені сторінки й ресурси.

## Публікація

Домен: `olmax.net.pl`, реєстратор GoDaddy, хостинг Railway. Стара версія доступна на
`https://www.olmax.net.pl`; нова версія з цієї гілки ще не розгорнута. Нижче також збережений
альтернативний спосіб запуску на власному VPS.

Застосунок потребує постійного Python ASGI-процесу та диска для SQLite/фото. Для VPS із Docker підготовлені `Dockerfile`, `compose.yaml`, `Caddyfile`. Потрібні вільні порти 80/443 та DNS домену й www, спрямовані на сервер. Не змінювати поштові MX/TXT записи.

На сервері спочатку задати пароль через `tools/setup_admin.py` і перевірити `.env`. Потім:

```sh
docker compose up -d --build
```

Caddy отримує HTTPS-сертифікат, передає запити застосунку й перенаправляє www на основний домен. Дані живуть у постійному томі `olmax_data`; не запускати `docker compose down -v`, бо це видалить дані. Увага: Docker-конфігурацію підготовлено, але ще не перевірено на реальному сервері.

Для cPanel спочатку перевірити підтримку Python ASGI або сумісного способу запуску. Поточний застосунок не можна просто завантажити як статичний HTML чи запустити через PHP. Розгортання слід адаптувати після перевірки тарифу, без придбання зайвих послуг наперед.

## Резервна копія

```sh
.venv/bin/python tools/backup.py
```

Архів у `backups/` містить узгоджену копію бази та фото, без активних сесій. Він містить звернення клієнтів — зберігати приватно. Для Docker можна виконати `docker compose exec app python tools/backup.py /data/backups`, потім скопіювати архів із контейнера на окремий носій. Автоматичний розклад копій ще не налаштований.

Відновлення: зупинити застосунок, зберегти поточну папку даних, розпакувати довірений архів у порожню папку даних, перевірити права власника й запустити застосунок. Не перезаписувати активну SQLite-базу. `.env` зберігається окремо.

## Перевірки

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Тести працюють із тимчасовими копіями даних: міграція, авторизація, CSRF, життєвий цикл оголошень, фото, заявки, ліміти й захист приватних файлів.
